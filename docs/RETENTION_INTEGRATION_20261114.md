# Retention integration and operator activation

The corrected PR11 is integrated with immediate sending PR12. Cleanup defaults off. Set MAIL_RETENTION_ENABLED=true and MAIL_RETENTION_USER_IDS to a comma-separated set of authorized MongoDB user IDs in the private root Compose .env to opt in. Compose explicitly forbids global cleanup for this deployment. Background cleanup runs hourly, with a48-hour UTC cutoff; Logs API shows only the current rolling48h window. Older detailed rows can persist until the next hourly tick. No send/worker/verification feature gate is enabled by this setting.

Before initial apply, back up the selected owner's eligible MailLogs privately, record a scoped dry-run, and use backend/scripts/retentionCleanup.js --apply --user <id> on the existing host. Never print secrets or put backups in git. Unknown/in-flight dispatches, contacts, companies, recipient suppressions and event receipts are retained. Campaign/dispatch message bodies are not compacted by this release.

Codex fixes added after independent integration: lease acquisition uses wall time independently of the injected retention cutoff clock; raw historical documents with missing optional fields can be compared/deleted exactly; canonical sender/contact/campaign/dispatch identities are checked; existing ledger status updates use compare-and-set so a concurrent authenticated bounce cannot be downgraded. Full source version comparison includes provider/hash, original optional-field absence, message content, updatedAt and revision. On conflict, details remain and operator review is required. Supplied13 retention regressions passed locally, including new raw-legacy and concurrent-ledger-bounce cases. Existing8/12 immediate corrections were retained; latest Compose browser test is included in CI after frontend build and Chromium installation.

Lease renewal limits overlap. Per-document compare-and-set protects outcomes even after lease expiry; no exactly-once distributed execution claim is made. Cleanup batches are bounded and retry-safe; a stuck/mismatched record is retained, not forcibly deleted.

Rollback: disable MAIL_RETENTION_ENABLED and restart the backend first. Restore backed-up detail rows only if needed without deleting their compact ledger evidence. Never roll back to a sender that ignores DeliveryLedger after pruning; retain compact-ledger duplicate/webhook/rollback protections. Do not drop suppression, receipt, campaign or dispatch collections. Compact delivery identity/outcome evidence remains without automatic expiry because duplicate prevention and late bounce correlation depend on it. Historical provider IDs absent in the original cannot be fabricated or guaranteed matchable.
