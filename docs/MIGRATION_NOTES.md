# Preservation and rollout notes

This change is a draft, not a production migration. Existing main was preserved. PR #1 was compared and left unmerged because its older diff would remove newer working features. Existing company seeds, job discovery, auth/settings and contact/mail history remain in the project.

- Salary evidence is additive. Existing tier/CTC estimates do not qualify employers. New directory seeding uses insert-only updates and canonical domains/aliases so subsequent starts do not overwrite reviewed compensation or manual corrections. Existing database duplicate companies are not automatically merged: job/contact references must be inspected first.
- Existing contacts without source/verification metadata remain unknown. MX validation now reports domain capability or inconclusive status; no domain whitelist creates mailboxes. Historical valid flags alone do not allow the research draft/send guards to treat a contact as sourced. An administrator must backfill genuine provenance; never manufacture it from company names.
- Source-less embedded recruiter registries remain legacy data files for comparison but are no longer exposed/imported as verified contacts. No existing production contact was deleted. Bounce cleanup quarantines records and retains linked mail logs.
- Candidate profile defaults no longer inject the owner's facts into new user accounts. Existing saved facts are retained for the applicant to review. The extension stores its own versioned, reviewed local profile; backend and extension profile synchronization is not automatic.
- The built extension now imports the shared tested engine. Old committed content.bundle.js is removed; root CRX/ZIP files are legacy and must not be used. Rebuild extension/dist, reload the extension and target tabs. The packaged extension does not expose source resume JSON as a web resource.
- Sending defaults off and requires exact recipient/content approval if separately enabled. The existing bulk composer has not yet been migrated to that approval contract; keep sending off. Resume uploads, final application submission, unknown/sensitive/legal questions and unsupported cross-origin form controls require manual action.
- Cloud deployment is manual dispatch. Local schedulers are opt-in. No AWS resource or live provider key was configured by this change.
- OneDrive reparse-point files prevent ordinary Git diffs/staging in the original workspace. Source edits remain there; a byte-copied clean checkout outside OneDrive at `C:/Users/khush/.codex/worktrees/jobfinder-publish-20261105` is used for reviewable commits/push. Original .git metadata is preserved. Use the published branch for further work or clone outside OneDrive; do not reset the original working tree to repair metadata.

Deployment gate: resolve remaining IMAP/SheetJS production dependency advisories, test actual employer DOMs with the selected real PDF, authenticate webhooks, complete mail approval UX/idempotency and independently review real salary/contact evidence before enabling sending. Fixtures and a synthetic local browser roundtrip do not establish live employer/provider compatibility.
