# Independent Smart Apply QA

Use the existing JobFinder repository and PR #32 (`feat/smart-apply-local-20261122`), not a new implementation. Read `docs/SMART_APPLY.md` and `docs/SMART_APPLY_PHASE0.md` first.

Task: independently verify the extension profile-import/answer-memory UI and collect reproducible, redacted widget regressions. Use a separate branch/worktree. No paid API calls, emails, application submissions, cloud provisioning, LinkedIn automation, CAPTCHA solving, OTP extraction or changes to production sending/worker flags. Use synthetic identities for local tests. Do not publish the user's resume, profile, login cookies, screenshots or contact data.

1. Build/load the extension and run the existing backend/form/Chromium suites. Test canonical JSON import -> explicit fact review -> preview -> fill; edit profile -> old preview invalid; answer -> approve/remember -> preview -> exact question fill; changed options/type/form URL -> no automatic reuse. Legal agreements, file selection, login challenges and final Submit must remain manual.
2. Exercise native selects, delayed portal dropdowns, `aria-haspopup=listbox` buttons, React-style controlled input updates, radio grouping, prefilled values, open shadow roots and frame duplicates. Record exact verified/needs-review counts and zero submissions. Do not call every synthetic widget a certified Workday or Google Forms adapter.
3. For public real forms, manually identify three current postings each for Greenhouse, Lever, Ashby and Workday, plus a non-production Google Forms test owned by the user. Record URL/date, accessible labels/widget kinds, whether public inspection is permitted, and missing adapter behavior. Do not automate blocked sites or logins. Real applicant data may only be filled after the user has reviewed the private profile. Stop before applying/submit, and do not create fake employer accounts or spam hiring systems with synthetic candidates.
4. Prefer a minimal local HTML reproduction and original test for each failure over copying a complete third-party page. Any real DOM/HAR/screenshot must have PII, form tokens and cookies removed before committing. Preserve provenance and licence status of any reused material; missing licence is not reuse permission.

Deliver: commit SHA, exact commands/results, table of actual sites inspected versus local fixtures, remaining failures with reproduction, and confirmation of zero submissions/paid calls. Do not claim all platforms work from local test passes. Do not merge/deploy or alter the main account's contacts or queues. Codex will independently verify and integrate findings.
